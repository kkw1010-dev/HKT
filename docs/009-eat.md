# 009 · Eat: eat from the inventory when Survival Mode hunger rises

Status (2026-09-18): tested in game. At hunger 80 (stage 4) the prompt offered
먹기: 감자 수프 (2 suitable foods). Accepting ate it, and hunger read 0 three
seconds later.

The user wanted iNeed's eat hotkey without installing iNeed. The modlist
already runs Survival Mode (Creation Club) with Survival Mode Improved (SKSE),
Starfrost and Gourmet, which are all Simonrim's. CIGAR does the eating itself;
no mod is added.

## What iNeed does (v1.95, read from its bundled `.psc`)

- Its hotkey opens a menu (`_SNOldConfig.HotkeyMenu`). "Eat" calls
  `_SNQuestScript.AutoEat(player)`.
- `AutoEat` walks its own food form lists in a fixed order, heavy → medium →
  soup → light (or the reverse, by an MCM option). It eats the first listed
  item the player carries, with `EquipItem(food, false, true)`.
- Everything else in iNeed (its needs, spoilage, water) is its own system. It
  would compete with Survival Mode, which is why the user does not install it.

## How hunger works on this modlist

- **Hunger value.** Survival Mode Improved (SMI) keeps it in
  `Survival_HungerNeedValue` (`00081A|ccqdrsse001-survivalmode.esl`). Starfrost
  sets the maximum to 120 and the stage thresholds (`Survival_HungerStage1..5Value`)
  to 1, 10, 20, 60 and 120.
- **Eating.** SMI lowers the value on the player's equip event for a food.
  This is `ProcessHungerOnEquipEvent` in `colinswrath/Survival-Mode-Improved-SKSE`,
  `include/Events.h`. For each of the four effects `Survival_FoodRestoreHunger
  VerySmall/Small/Medium/Large` (`002EE1`–`002EE4|Update.esm`), SMI subtracts
  the matching `Survival_HungerRestore*Amount` global.
  - Starfrost sets all four globals to 125, so any hunger food fully sates.
  - 332 foods on this modlist carry one of the four effects, most through
    Gourmet and its patches. Their magnitudes are 0; the tier alone decides.
- **Raw food.** SMI rolls food poisoning (50%, less with disease resistance)
  for food in `Survival_FoodRawMeat` (`0008B0`) or with `VendorItemFoodRaw`
  (`0A0E56|Skyrim.esm`).
- **Survival on.** `Survival_ModeEnabled` (`000826`) is 1 while Survival Mode
  runs. SMI also has `SMI_HungerShouldBeEnabled` (`000F27|SurvivalModeImproved.esp`).

## CIGAR's module

The 먹기: <음식 이름> prompt is shown while all of these hold:

- Survival Mode is on, and SMI's hunger switch is on when SMI is loaded;
- the hunger stage is at least the control panel's 표시 시작 허기 단계
  (1–5, default 3, saved as `eat.minStage`);
- the player is out of combat, has movement controls, and is not in a SexLab
  scene;
- 3 s have passed since the last bite;
- the inventory holds a suitable food.

**Which food.** Of the suitable foods, the cheapest (gold value, then weight,
then FormID). Every tier fully sates under Starfrost, so the cheapest food is
spent first; this was the user's choice. A food is suitable when it:

- is a food (`AlchemyItem::IsFood`) with one of the four hunger effects;
- has no hostile or detrimental effect. On this modlist this rules out two
  meads and BaboDialogue's drugged "suspicious" food;
- is not raw: not in `Survival_FoodRawMeat` and without `VendorItemFoodRaw`;
- when Gourmet is loaded, has none of Gourmet's `MAG_FoodItemRaw`,
  `MAG_FoodTypePoisoned`, `MAG_FoodItemDrugs`, `MAG_FoodTypeDrugs`,
  `MAG_FoodTypeAle` or `MAG_FoodTypeWine`;
- is not a quest item.

**Eating.** Accepting re-checks the gate and calls
`ActorEquipManager::EquipObject(player, food)`. This is the same equip the
inventory menu performs, so SMI and eating animations (Taberu) react. When the
pick changes while the prompt is up (the stack ran out, a cheaper food was
picked up), the prompt is offered again with the new name.

## Self-reporting

- At load, `CIGAR.log` logs what resolved (`Survival mode=… stages=…
  effects=… gourmet=… excludedKeywords=…`). If Survival Mode is present but its
  forms do not resolve, a notification appears once.
- The gate line shows the stage, not the hunger value, which changes every few
  seconds. It also shows the number of suitable foods and the pick.
- Every bite logs the food, its value, and the hunger value before it. The
  first tick after the 3 s pause logs the value after it. If hunger did not
  drop, a notification appears once, because SMI then did not see the equip.
- `verify_deploy.py` reads every FormID this module hard-codes from the
  plugins and fails when its EditorID differs.
